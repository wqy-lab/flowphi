# 黄键接续

黄键（Drag）不需要新的按下事件。生成器现在把“用已有触点接住黄键”纳入正常候选搜索，同时保留重新按下、换指的候选；以前只有新动作全部失败后才尝试复用。

实现位于 `flowphi/planning/drag_continuation.py`，由 `Planner.run` 调用：

- 已按住的 Hold、Tap、Flick 或 Drag 可以共同覆盖后续黄键。保留原来的音符 ID、独立按下和滑键轨迹，校验重叠判定区域。
- 已结束的动作可以保持按住并滑向黄键，但不改写原有控制点；只生成新的尾段，并检查速度、碰撞、手指占用和遮挡。
- 只搜索每根手指最近的动作，空档最长 0.35 秒。这是动作候选的搜索范围，不是游戏判定窗口。
- 完全不改变已有触点位置和持续时间的复用，不会因原动作已有的姿态警告而被拒绝；原警告仍保留。增加移动或延长触控时，新增区间仍需通过运动约束，但不计算一次新的抬指转移。
- 后续 Tap、Hold 仍需要独立按下。不能穿过遮挡来维持接续，也不会为了接黄键重写原 Flick 的滑动。

目前对仍在持续的长按，只尝试沿原轨迹接住黄键；需要主动调整长按轨迹时，仍可能分配额外手指。

`tests/test_drag_continuation.py` 覆盖上述接续、移动黄键链、真实导出后的按下次数，以及继承已有碰撞警告的情况。运行全部回归检查：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

修改生成器不会自动重写已保存的指法。旧项目需要重新生成，或在副本上调整后再检查。

## 实谱核对

使用本地《Entrance to the Chaos》IN，截取谱面时间 136.812–141.449 秒的结尾（4 条长按、260 个黄键），保留原判定线事件，默认启用全部手指。仅对比黄键策略，双方都使用当前垂直判定区域实现；这是尾段独立生成结果，不是整首曲目的验证。

| 项目 | 原黄键策略 | 接续候选策略 |
| --- | ---: | ---: |
| 生成触控段 | 259 | 4 |
| 内部判定区域错误 | 3 | 0 |
| 未规划音符 | 0 | 0 |

新版导出后重新读取触控数据，确认只有 4 次实际按下：保留 4 个长按头，260 个黄键全部由已有长按触点覆盖，最后将该触点延长到 141.462 秒。验证结果与实际导出的触控数据哈希一致。工程和报告保存在本地 `.local/drag-eval/after-all/`。

原有 3 条长按动作的 `pad_collision` 警告仍保留；本次没有解决这组长按的手型拥挤问题。全部 43 项回归测试通过。

## 接续搜索性能

接续搜索现在只向验证器传入当前时间窗口相关的音符，复用同轨迹、同窗口、同判定约束的验证结果；轨迹采用写时复制，拒绝候选时不再深拷贝整段动作。没有新增运动时不重复计算整段行程。

规划器专用的判定区域缓存有容量上限。明确位于判定矩形内部的点采用带数值余量的坐标投影检查；边界和自定义区域仍使用原多边形检查，遮挡检查始终保留。采样仍为 1 毫秒，候选数量和搜索宽度没有缩减。最终导出检查不启用这些规划器缓存和内部点快速路径。

同一尾段、默认全部手指的本机耗时记录（秒，单次运行，含环境波动）：

| 项目 | 优化前接续版 | 优化后 |
| --- | ---: | ---: |
| 生成动作 | 152.35 | 27.4 |
| 生成及完整检查 | 168.72 | 43.66 |

生成阶段约快 5.6 倍。优化前后的已验证触控数据 SHA-256 完全一致，仍为 4 次按下、覆盖全部 264 个音符。优化结果保存在本地 `.local/drag-eval/optimized-final-all/`。全部 46 项测试通过，新增测试对照独立多边形验证，覆盖旋转/移动判定线、遮挡、边界容差和历史窗口裁剪。

内部检查通过只表示触控覆盖、判定区域及占用检查通过；自然姿态、皮肤碰撞和官方游戏 AP 仍需分别验证。
