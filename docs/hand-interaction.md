# 手指交叉与交互段规划

手腕左右顺序只保留为辅助代价。`planning/interaction.py` 增加独立的手指交叉、对侧掌面穿行、左右指尖顺序倒置和指根侧向扭转指标；投影交叉不会因为手指在高度上错开而被忽略。它们是软代价，不能放松原有触控、占用、碰撞、速度或关节硬限制。

普通候选使用手型与朝向构造指根到指尖及掌面近似。新动作按下前最多 250 毫秒的准备/转移、对侧触点抬起后最多 300 毫秒的释放也参与评分，因此交互中“从不同时按下”的两根手指仍可能产生交错代价。历史搜索保留每指最近动作及当前区间内的动作，旧长按不会被较新的短触点遮掉。持续代价按时间积分，接续只补收同一上下文下延长/移动产生的差额。

黄键窗口的候选评估直接使用共享受限骨架已经计算的帧，包括准备、释放与转移。检查所有手指链的投影交叉、手指穿过另一手掌的比例，以及指尖左右顺序和相对掌面朝向的侧向偏转。闲置手指的几何仍由原硬碰撞检查保留；软交互按动作影响权重计费。手掌取凸包以适应左右手顶点次序。

普通搜索不新增 IK：约 50 毫秒采样，每个触控最多 128 个软采样；身份缓存保留路径所有权，最多 1024 条。窗口评估复用原有硬审查帧，不增加手部候选数量或降低毫秒级验证精度。局部 32 状态、每类 16 个触控候选/8 个手部评估、外层 `beam_width` 均保持原上限。

设置 `hand_interaction_weight` 默认 1，0 可用于代码层的前后对照。普通评分保存 `decision.costs.interaction` 与 `decision.interaction`；手部报告保存 `interaction` 的加权持续时间、峰值及独立代价。改变这个权重不改变任何硬检查的通过条件。

普通规划屏幕边缘已与独立几何验证共用 `SCREEN_MARGIN=0.012`，额外向内留 `0.00001` 的数值保护。旧规划允许 1%/99% 触点而独立验证只允许 1.2%/98.8%，新评分更容易选到这些不合法的边缘位置；现在收紧生成区域，不改变独立验证标准。新增边缘候选的毫秒级独立验证回归用例。

验证脚本位于 `.local/check_aapa_interaction.py`（同一受限骨架的整首诊断）、`.local/generate_aapa_interaction.py`（使用用户 AAPA IN 双指设置另存重生成）、`.local/benchmark_aapa_interaction.py`（104–112 秒相同前文的顺序耗时对照）。整首统计按 12 Hz 取样，是动作比较材料，不替代原有 60 Hz/事件边界的硬审查。该实现仍不是完整手部蒙皮或最终摄像机视角下的无穿模证明。
